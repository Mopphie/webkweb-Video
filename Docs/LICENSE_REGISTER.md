## C — Apple-Prüfung

[App Review Guidelines](https://developer.apple.com/app-store/review/guidelines/) insbesondere 2.5.1/2.5.4/2.5.6 (öffentliche APIs, tatsächliche Audio-Hintergrundnutzung, WebKit), 4.2 (eigener App-Nutzen), 5.1 (Datenschutz), 5.2.1–5.2.3 (Marken/Dienste/Downloads). Eigene Datei-/Mediatheks-/Notiz-/Queuefunktionen schaffen nativen Nutzen; das ist **keine Zusage der Annahme**.

- [Nicht persistenter WK-Store](https://developer.apple.com/documentation/webkit/wkwebsitedatastore/nonpersistent()) technisch eingesetzt; keine Anonymitätsgarantie.
- [WK-PiP-Konfiguration](https://developer.apple.com/documentation/webkit/wkwebviewconfiguration/allowspictureinpicturemediaplayback) erlaubt Systemmöglichkeiten, erteilt keine fremden Medienrechte. Native AVKit-Funktionen stehen nur berechtigten eigenen/Direktmedien zur Verfügung.
- [App Privacy Details](https://developer.apple.com/app-store/app-privacy-details/) unterscheidet Open-Web-Navigation von sonstigen Webviews. Deshalb keine automatische Aussage „keine Daten erhoben“: gezielte Dienste, Server-/Websitedaten und Store-Angaben müssen im finalen Produktkontext bewertet werden.
- [User Privacy and Data Use](https://developer.apple.com/app-store/user-privacy-and-data-use/): keine eigenen Tracking-/Werbe-SDKs, keine Tracking-Zusammenführung. Website-Tracking wird dadurch nicht pauschal ausgeschlossen.
- App-/Widget-/Share-Privacy-Manifests nennen UserDefaults-Gründe CA92.1/1C8F.1 für eigene Einstellungen/App-Group-Übergaben. Keine zusätzlichen nötigen Timestamp-/Disk-/Fingerprint-Aufrufe in eigenem Produktionscode gefunden; finalen SDK-/Archive-Privacy-Report noch erzeugen.
- Neue ShareExtension benötigt eigene gültige App-ID/Provisionierung mit vorhandener Gruppe; **nicht eingerichtet**, kein produktives Konto verändert.
