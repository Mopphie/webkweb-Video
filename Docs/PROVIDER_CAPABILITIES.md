## Navigation und Darstellung

Die native Watch-Ansicht verändert nur App-Chrome. YouTube-Masthead, Kommentare, Vorschläge, Shorts, Werbung, Playerantworten und Video-Farben werden nicht manipuliert. Ein sichtbarer Abwärts-/Zurückknopf, Start und das feste Aktionen-Sheet sind erreichbar; Herunterwischen ist nur eine zusätzliche Geste. Ohne Browserhistorie gibt es einen Start-Ausweg, auch am Tablimit. iPad zeigt eine Tabzeile sowie bei nativen Medien Player und Queue nebeneinander; kleine Querformate verwenden kleinere Playerhöhe. Layout/VoiceOver/Dynamic Type müssen am Gerät abgenommen werden.

## Hintergrund, PiP, AirPlay und Audio — getrennte Zusagen

- **System-PiP:** AVKit bietet es für native berechtigte Medien nach Systemverfügbarkeit an; Wiederherstellung verweist auf denselben Player. Kein extrahierter Website-Stream und kein universeller PiP-Button.
- **App-Miniplayer:** Derselbe AVPlayer bleibt beim Navigieren in der App erhalten; Größe/Fokus ändern nur die Darstellung. Kein zweiter Player. Ein beginnender Websiteplayer beendet den nativen Player; umgekehrt wartet native Wiedergabe auf WebKits Pausebestätigungen.
- **Hintergrund-Audio:** Native AVPlayer-Richtlinie `audiovisualBackgroundPlaybackPolicy = .continuesIfPossible` (öffentliche API seit iOS 15) und `.playback`-Session werden nur für berechtigte native Medien eingesetzt; die Session wird bei tatsächlichem Start aktiviert und bei Ruhe wieder freigegeben. Der Appwechsel pausiert normale native Medien nicht. Websiteanbieter können ihre Wiedergabe selbst anhalten. Ein Timer beweist keine ununterbrochene iOS-Ausführung.
- **Systemsteuerung:** Eigene Now-Playing-Daten nur für den normalen nativen Player; Pause/Ende/Schließen aktualisieren bzw. entfernen sie. Website-Now-Playing wird nicht in einer Schleife überschrieben. Private Websiteinhalte werden nicht app-seitig publiziert.
- **AirPlay:** Öffentlicher AVRoutePicker und AVPlayer-Routing; Abziehen/Unterbrechung pausiert sicher. Verbindung, Geräteverlust, Bluetooth und tatsächliches Empfängerverhalten sind noch zu testen. Keine Filterung auf dem Empfänger zugesagt.
- **App-Sperre:** Schützt die Appoberfläche; privat/bei aktivierter Sperre wird die Vorschau verdeckt, einschließlich Sheets. Bewusst gestartete normale native Systemwiedergabe kann weiterlaufen. Die Sperre ist keine Vollverschlüsselung und kein DRM.

Technische Definitionen: `App/SourceCapabilities.swift`, `BrowserTab.canControlMedia`, `NativePlayer.swift`. Die Plattformbegrenzung prüft sowohl Hauptseitenhost als auch aktiven Framehost; die vollständige Entfernung von Ressourcenfiltern wirkt zusätzlich unabhängig von Hostlisten bei Einbettungen/Unterressourcen. Eine Hostliste alleine wäre dafür kein ausreichender Beweis.
